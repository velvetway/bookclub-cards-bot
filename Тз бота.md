# ТЗ: телеграм-бот раздачи карточек книжного клуба

Версия 1.0

---

## 1. Назначение

Бот раздаёт участникам клуба персональные карточки в личные сообщения по команде администратора. Карточка — угол или обязательный элемент, который участник встраивает в свой устный разбор книги на встрече.

Ключевое свойство: карточка приходит лично и до встречи, содержимое чужих карт неизвестно до момента, когда человек начинает говорить.

**В рамки входит:** управление колодой, состав участников, раздача, доставка, история выдач.

**В рамки не входит (MVP):** сбор оценок, голосование за книгу, трекинг прогресса чтения, генерация карточек-картинок.

---

## 2. Роли

|Роль|Права|
|---|---|
|**Админ**|всё: раздача, колода, участники, история, настройки|
|**Участник**|получает карты в ЛС, смотрит свою историю, реролл (если включён)|

Админов может быть несколько, задаются списком ID в конфиге. Первый запустивший бота при пустой базе админов становится админом автоматически.

---

## 3. Термины

- **Карта** — единица колоды. Имеет код, тип, название, пояснение.
- **Тип** — `optics` (оптика) / `insert` (врезка) / `rating` (к оценке).
- **Книга** — цикл чтения. Может длиться 1–3 недели.
- **Раздача (deal)** — одно событие выдачи карт: книга + тип + состав + назначения.
- **Назначение (assignment)** — связка «участник ↔ карта» внутри раздачи.
- **Черновик** — раздача, сгенерированная, но не отправленная.

Для одной книги может быть несколько раздач: оптика уходит вместе с объявлением книги, врезка — за день до встречи. Это разные раздачи.

---

## 4. Основной сценарий

1. Админ вызывает мастер раздачи.
2. Выбирает книгу (текущую или создаёт новую).
3. Выбирает тип раздачи: оптика / врезка / к оценке / смешанная.
4. Выбирает состав — кто читает эту книгу. По умолчанию все активные.
5. Выбирает пул: вся колода / только выбранный тип / произвольный набор карт.
6. Бот генерирует черновик и показывает превью: список «участник → карта».
7. Админ правит: реролл одному, обмен между двумя, ручная замена карты, перегенерация всего, исключение участника.
8. Подтверждает отправку.
9. Бот рассылает карты в ЛС, показывает отчёт о доставке.
10. Опционально постит в группу объявление без содержимого карт.

Черновик хранится в базе. Если админ вышел из мастера, черновик доступен для продолжения — важно, потому что работа идёт с телефона.

---

## 5. Краевые сценарии

**Участник не запускал бота.** Бот не может написать первым. Такой участник помечен в списке состава значком и по умолчанию не выбран. При попытке включить его — предупреждение. Решается разовым онбордингом (раздел 9).

**Участник заблокировал бота.** Отправка падает с `Forbidden`. Участник помечается неактивным, админ видит это в отчёте.

**Частичная доставка.** Если часть сообщений не ушла, раздача получает статус `partial`. Отчёт показывает список неудач с причиной. Кнопка «повторить недоставленные» — повторная отправка только тем, у кого статус `failed`. Повторная отправка не меняет уже выданные карты.

**Пул меньше числа участников.** Раздача блокируется с сообщением, сколько карт не хватает.

**Все карты пула попали в окно неповторения.** Окно ослабляется автоматически (берётся карта с самой старой выдачей у этого участника), в превью — пометка «повтор от <дата>».

**Двойная отправка.** Раздача со статусом `sent` не отправляется повторно. Повтор возможен только через явное «отправить заново» с подтверждением.

## 6. Модель данных

SQLite. Таблицы:

**users**

```
id            INTEGER PK        -- telegram user_id
username      TEXT
display_name  TEXT              -- как показывать в списках
is_active     BOOL DEFAULT 1
is_admin      BOOL DEFAULT 0
started_at    TIMESTAMP         -- когда нажал /start, NULL = писать нельзя
```

**books**

```
id            INTEGER PK
title         TEXT NOT NULL
author        TEXT
weeks         INTEGER           -- 1..3
started_at    DATE
meeting_at    TIMESTAMP
status        TEXT              -- planned | current | done
```

**cards**

```
id            INTEGER PK
code          TEXT UNIQUE       -- OPT-01, INS-07, RAT-03
type          TEXT              -- optics | insert | rating
title         TEXT NOT NULL
hint          TEXT              -- пояснение под названием
is_active     BOOL DEFAULT 1
book_id       INTEGER NULL      -- если карта написана под конкретную книгу
created_at    TIMESTAMP
```

**deals**

```
id            INTEGER PK
book_id       INTEGER FK
phase         TEXT              -- optics | insert | rating | mixed
pool_mode     TEXT              -- all | by_type | custom
pool_codes    TEXT NULL         -- JSON-список кодов при custom
status        TEXT              -- draft | sent | partial | cancelled
created_at    TIMESTAMP
sent_at       TIMESTAMP NULL
```

**assignments**

```
id            INTEGER PK
deal_id       INTEGER FK
user_id       INTEGER FK
card_id       INTEGER FK
status        TEXT              -- pending | sent | failed | skipped
error         TEXT NULL
sent_at       TIMESTAMP NULL
reroll_count  INTEGER DEFAULT 0
manual        BOOL DEFAULT 0    -- назначено админом вручную
```

**settings** — ключ-значение: окно неповторения, число рероллов, ID группы, шаблон сообщения.

Индексы: `assignments(user_id, card_id)`, `assignments(deal_id)`, `cards(type, is_active)`.

## 7. Алгоритм раздачи

```
вход: список участников U, пул карт P, окно неповторения W

1. Отфильтровать P: только is_active
2. Если len(P) < len(U) → ошибка
3. Перемешать U (чтобы порядок не давал преимущества)
4. Для каждого участника u:
   a. recent = последние W карт, выданных u (по assignments)
   b. candidates = P минус recent минус уже назначенные в этой раздаче
   c. если candidates пуст:
        candidates = P минус назначенные в этой раздаче
        пометить назначение флагом "повтор"
   d. выбрать карту с учётом весов типа (если pool_mode != custom)
   e. записать назначение
```

**Веса по типам** (применяются при `all` и `mixed`): оптика 20% / врезка 65% / к оценке 15%. При `by_type` и `custom` — равномерно внутри набора.

**Окно неповторения** — по умолчанию 10 последних выдач этому участнику. Настраивается.

**Ограничение на оптику**: если участник получал карту типа `optics` в одной из трёх последних раздач, оптика ему не выпадает. Оптика перестраивает всю подготовку, это нагрузка, а не бонус.

**Приоритет книжных карт**: если у книги есть собственные карты (`book_id` совпадает), они получают повышенный вес — при прочих равных выпадают первыми.

## 8. Команды и интерфейс

Управление — инлайн-кнопками, не текстовыми командами. Всё делается с телефона.

**Участник**

|Команда|Действие|
|---|---|
|`/start`|регистрация, при переходе по диплинку — привязка к клубу|
|`/me`|моя текущая карта|
|`/history`|мои прошлые карты|
|реролл|кнопка под картой, если разрешено настройкой|

**Админ**

|Команда|Действие|
|---|---|
|`/menu`|главная панель|
|`/deal`|мастер раздачи|
|`/cards`|колода: список, добавить, править, включить/выключить|
|`/book`|книги: создать, сделать текущей, закрыть|
|`/members`|участники: список, статус, деактивация|
|`/who`|кто что получил по текущей книге|
|`/stats`|частота карт, распределение по участникам|
|`/settings`|окно неповторения, рероллы, группа, шаблон|

**Выбор произвольного пула** — два способа:

- инлайн-список карт с переключателями, постранично по 8
- быстрый ввод кодов строкой: `INS-03 INS-07 OPT-02`

**Превью раздачи** — сообщение вида:

```
Книга: «К югу от границы, на запад от солнца»
Тип: врезка · 7 участников

1. Сергей     — INS-09 Ножницы
2. БП         — INS-18 На чём держится
3. ...

[перегенерировать] [править] [отправить]
```

Правка — выбор строки, затем «реролл / заменить вручную / убрать участника».

## 9. Онбординг

Разовая процедура, без неё схема не работает.

1. Админ вызывает «пригласить» и получает диплинк вида `https://t.me/<bot>?start=join`.
2. Ссылка кидается в групповой чат.
3. Каждый участник переходит, бот регистрирует его, заполняет `started_at`.
4. В `/members` админ видит, кто подключился, а кто нет.

Пока `started_at` пуст, участнику нельзя отправить ничего.

## 10. Сообщение с картой

Шаблон настраивается. По умолчанию:

```
Книга: «<название>»
Встреча: <дата>

<НАЗВАНИЕ КАРТЫ>
<пояснение>

Эту карту нужно встроить в свой разбор.
Чужие карты неизвестны — не обсуждайте до встречи.
```

Для оптики добавляется строка о том, что карта задаёт угол всего рассказа.

Опциональный пост в группу после раздачи — только факт и состав, без содержимого:

```
Карты розданы: 7 участников. Встреча <дата>.
```

## 12. Стек и эксплуатация

- Python 3.11+, **aiogram 3.x**, long polling
- SQLite, доступ через `aiosqlite` или SQLAlchemy
- Развёртывание: VPS, systemd-юнит, автоперезапуск
- Логи: файл + ротация; каждая отправка пишется в лог с результатом
- Бэкап: ежедневная копия файла базы, хранить 30 дней
- Пауза 0.05 с между отправками (запас по лимитам Telegram)

Нагрузка — десяток пользователей и несколько десятков сообщений в неделю. Ни очередей, ни отдельной БД, ни вебхуков не требуется.

---

## 13. Приёмка

Бот считается готовым, если:

1. Новый участник по диплинку регистрируется и появляется в `/members`
2. Раздача на 7 человек уходит в ЛС, отчёт показывает 7 доставленных
3. При заблокированном боте у одного участника раздача получает статус `partial`, повтор доставляет остальным без дублей
4. Карта не повторяется у одного участника в пределах окна
5. Оптика не выпадает одному человеку два цикла подряд
6. Произвольный пул из 5 карт корректно раздаётся на 5 человек и падает с ошибкой на 6
7. Черновик переживает выход из мастера
8. `/who` показывает актуальную картину по текущей книге

## 14. Этапы

**Этап 1 — ядро.** Онбординг, участники, колода (загрузка 31 карты из файла), раздача с превью и правкой, доставка, отчёт, история. Это рабочий продукт.

**Этап 2 — по факту использования.** Карточки как изображения (шаблон + наложение текста), карты под конкретную книгу, чекпоинты для двух- и трёхнедельных книг.

**Этап 3 — если клуб приживётся на боте.** Сбор числовых оценок после встречи, статистика по книгам и участникам, спорность книги по разбросу оценок.

Этап 3 стоит держать в голове при проектировании базы, но не реализовывать заранее.
