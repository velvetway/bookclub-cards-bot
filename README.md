# Бот раздачи карточек книжного клуба

Раздаёт участникам персональные карточки в личку по команде админа. Карточка —
угол или обязательный элемент, который человек встраивает в свой устный разбор
книги на встрече. Карта приходит лично и до встречи; чужие карты неизвестны,
пока человек не начал говорить.

Колода — 31 карта: 6 оптики, 20 врезок, 5 к оценке. Управление целиком
инлайн-кнопками: всё делается с телефона.

Техзадание — [Тз бота.md](Тз%20бота.md), тексты карт — [Карточки.md](Карточки.md).

## Что умеет

- онбординг по ссылке-приглашению, список участников с отметкой «не нажимал /start»
- мастер раздачи: книга → тип → состав → пул → превью → правка → отправка
- правка превью: реролл, обмен между двумя, ручная замена, исключение участника, перегенерация
- черновик живёт в базе и переживает выход из мастера
- доставка с отчётом, повтор только недоставленных, защита от двойной отправки
- карточка уходит картинкой, пояснение — отдельным сообщением
- история выдач по каждой книге и по каждому участнику, статистика по колоде
- окно неповторения, кулдаун оптики, веса типов, приоритет карт под книгу

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

В `.env` вписать `BOT_TOKEN` от [@BotFather](https://t.me/BotFather). Остальное
можно не трогать — значения по умолчанию рабочие.

```bash
.venv/bin/python -m bot.main
```

При первом запуске создаётся база и в неё заливается колода из `data/deck.json`.

## Первый запуск

1. Нажать `/start` — первый, кто это сделал при пустой базе админов, становится админом.
2. `/members` → «Пригласить» → кинуть ссылку в чат клуба. Пока участник не нажал
   «Старт», бот не может написать ему первым — это ограничение Telegram, не бота.
3. `/book` → создать книгу, назначить дату встречи.
4. `/deal` → мастер раздачи.

## Настройки

В `.env` лежат значения по умолчанию, в `/settings` — то, что админ поменял.
База всегда главнее файла.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `BOT_TOKEN` | — | токен от @BotFather |
| `ADMIN_IDS` | пусто | список ID админов через запятую |
| `GROUP_CHAT_ID` | пусто | чат для объявлений о раздаче |
| `DB_PATH` | `data/bot.db` | файл базы |
| `TZ` | `Europe/Moscow` | часовой пояс дат в сообщениях |
| `NO_REPEAT_WINDOW` | 10 | сколько последних выдач блокируют повтор карты |
| `OPTICS_COOLDOWN` | 3 | через сколько раздач участнику снова может выпасть оптика |
| `REROLLS_PER_DEAL` | 1 | рероллов на участника, 0 — выключено |

## Картинки карточек

Бот ищет файл по коду карты: `data/cards/OPT-01.png` (годятся `.png`, `.jpg`,
`.jpeg`, `.webp`). Если файл есть — участнику сначала приходит картинка, следом
отдельным сообщением пояснение и правила. Если файла нет — уходит одно текстовое
сообщение. Загруженный файл кешируется по `file_id`, второй раз не заливается;
подменишь картинку на диске — кеш сбросится сам.

Как сделать колоду:

```bash
# 1. промпты (уже собраны, пересобирать только если правил prompts/scenes.json)
.venv/bin/python scripts/build_prompts.py

# 2. сгенерировать 31 картинку по prompts/card_prompts.md,
#    разложить в data/cards/raw/ под именами OPT-01.png, INS-07.png и т.д.

# 3. впечатать названия
.venv/bin/pip install -r scripts/requirements.txt
.venv/bin/python scripts/make_cards.py
```

Название печатает скрипт, а не модель: кириллицу генераторы пишут криво и
по-разному от карты к карте, а подпись должна быть одинаковой во всей колоде.
Промпты поэтому запрещают любой текст и просят оставить низ кадра спокойным.

У каждой карты свой кот и своя локация — окрас, возраст и характер подобраны
под смысл карты. Общей остаётся только манера рисунка, она вклеена в каждый
промпт дословно.

Скрипт заодно рисует окантовку. Кайма нужна не для красоты — без неё половина
картинок сливается с фоном в тёмной теме Telegram, а под акцентной линией лежит
тёмная подложка, иначе линия пропадает на светлых сценах вроде летнего луга.

Колоды отличаются и цветом, и рисунком рамки — на маленькой картинке в ленте
один только оттенок не читается. Задаётся в `data/covers.json`:

| Колода | `accent` | `border` | Как выглядит |
|---|---|---|---|
| базовая | золото | `double` | две линии, прямые засечки в углах |
| детективная | бордо | `deco` | одна линия, ступенчатые углы |

Отключается флагом `--no-border`.

## Обложки колод

Обложка — рубашка: её можно показать, не раскрывая содержимого карт. Лежит в
`data/covers/`, описывается в `data/covers.json`, промпты — в
`prompts/covers_prompts.md`.

Команда `/cover` (или пункт меню) показывает обложку под текущую книгу и
предлагает отправить её в группу вместе с названием книги и датой встречи.
Отправка ручная: бот сам в группу ничего не пишет.

Какая обложка какой книге — определяется по кодам её карт: если у книги есть
свои карты с префиксом `ACK`, берётся детективная обложка, иначе базовая.
Заводить новую книжную колоду можно без правок в настройках — достаточно
дописать строку в `data/covers.json` с её префиксом, цветом и рисунком рамки.

## Книжные колоды

Карта может быть написана под конкретную книгу. Такие колоды лежат в
`data/decks/`, заливаются скриптом и привязываются к книге через `cards.book_id`:

```bash
python scripts/load_deck.py data/decks/ack.json --make-current
```

Когда раздача идёт по этой книге, её карты выпадают первыми — алгоритм даёт им
повышенный вес. В остальных раздачах они участвуют наравне с общими, так что
после встречи их обычно стоит выключить в `/cards`.

Промпты к книжной колоде собираются оттуда же:

```bash
python scripts/build_prompts.py --scenes prompts/scenes_ack.json
python scripts/build_prompts.py --all      # все колоды разом
```

Манеру рисунка книжная колода не описывает заново, а ссылается на основную
(`"style_from": "scenes.json"`) — чтобы книжные карты не выбивались из стопки.

Готовые колоды:

- [«Убийство Роджера Экройда»](docs/ackroyd.md) — 10 карт, врезка. Памятка
  раскрывает финал, читать после книги.

## Как раздаются карты

Для каждого участника по очереди, порядок участников перемешивается:

1. карты, занятые другими в этой же раздаче, не рассматриваются — это не ослабляется;
2. если участник получал оптику в последних `OPTICS_COOLDOWN` раздачах, оптика ему не выпадает;
3. карты из окна неповторения (`NO_REPEAT_WINDOW` последних выдач) не выпадают.

Если под всеми тремя условиями не осталось ничего, сначала ослабляется окно
неповторения — берётся карта с самой старой выдачей, и в превью появляется
пометка «повтор от такой-то даты». Кулдаун оптики ослабляется последним, а если
пул состоит только из оптики (раздача оптики), он не применяется вовсе.

Веса типов 20 / 65 / 15 работают, когда пул — вся колода; при пуле «только тип»
и произвольном наборе карты внутри набора равновероятны. Карта, написанная под
текущую книгу, весит втрое больше обычной.

Окно неповторения и кулдаун считаются по фактически доставленным картам: если
сообщение не дошло, карта не засчитывается как выданная.

## Эксплуатация

```bash
sudo cp deploy/bookclub-bot.service /etc/systemd/system/
sudo systemctl enable --now bookclub-bot
journalctl -u bookclub-bot -f
```

Логи пишутся и в файл: `logs/bot.log`, ротация по 2 МБ, 5 файлов. Каждая
отправка попадает в лог с результатом.

Бэкап базы — `scripts/backup.sh`, снимает копию через `sqlite3 .backup`
(безопасно на работающем боте) и хранит 30 дней:

```
0 4 * * * /opt/bookclub-cards-bot/scripts/backup.sh >> /var/log/bookclub-backup.log 2>&1
```

## Тесты

```bash
.venv/bin/python -m pytest
```

`tests/test_dealer.py` — алгоритм раздачи, `tests/test_flow.py` — сквозные
сценарии на реальной базе с подменённым Telegram: доставка, `partial` при
заблокированном боте, повтор недоставленных без дублей, окно неповторения,
кулдаун оптики, черновик, картинки.

## Структура

```
bot/
  main.py          запуск, long polling
  config.py        .env
  db.py            схема SQLite и миграции
  models.py        типы предметной области
  dealer.py        алгоритм раздачи, без базы — его и тестируем
  service.py       склейка алгоритма с базой: генерация, реролл
  delivery.py      рассылка, отчёт, объявление в группу
  images.py        поиск картинки карты и кеш file_id
  texts.py         тексты сообщений
  keyboards.py     инлайн-клавиатуры
  callbacks.py     фабрики callback_data
  storage/         доступ к данным, по модулю на таблицу
  handlers/        роутеры: онбординг, участник, мастер, колода, книги, участники, статистика, настройки
data/
  deck.json        31 карта
  cards/           картинки карточек, raw/ — исходники до подписи
prompts/           стиль и промпты для генерации картинок
scripts/           сборка промптов, подпись картинок, бэкап
deploy/            systemd-юнит
```

## Отступления от ТЗ

- В `assignments` добавлена колонка `repeat_of` — дата прошлой выдачи карты, если
  окно неповторения пришлось ослабить. Без неё нечего показывать в пометке
  «повтор от <дата>», которую требует ТЗ.
- В `cards` добавлены `image_path`, `image_file_id`, `image_sig` — для картинок
  карточек и кеша Telegram.
- Кулдаун оптики не применяется, когда пул состоит только из оптики: иначе
  раздача оптики была бы невозможна.
- В колоде записано «оптика не чаще раза в 4 встречи», в ТЗ — 3 раздачи.
  По умолчанию стоит 3, как в ТЗ; меняется в `/settings` без правки кода.
